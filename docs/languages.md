# FileWarden language preference

The General setting controls texts generated by FileWarden in administration, public library frames, protected viewers and notifications. It is a shared plugin preference, independent of WordPress core and other plugins. Native Media Library controls retain their WordPress language; resource/user names and machine-readable audit/export keys are not translated.

`auto` follows the site's persisted `WPLANG`, not the administration request/user locale. English is used for the default/unsupported language; French regional variants use the bundled French catalog. Explicit choices are `fr_FR` and `en_US`. A fixed locale registry prevents arbitrary file paths. The chosen catalog is redirected only for the `filewarden` text domain; no global locale filter or language switch changes other domains. Save validation requires the existing settings capability and admin nonce. A successful POST redirects so PHP, localized JavaScript, public frames and notifications load the same saved preference on their next request.

## Maintaining catalogs

Use WordPress's native gettext functions with literal strings, the `filewarden` domain, translator comments/placeholders and plural forms. JavaScript text is provided by localized configuration/data attributes; do not hardcode user-facing English in scripts.

```sh
wp i18n make-pot . languages/filewarden.pot --exclude=.tools,build,vendor,assets/pdfjs --skip-js --skip-audit
wp i18n update-po languages/filewarden.pot languages/filewarden-fr_FR.po
# Review and translate every new/fuzzy entry before continuing.
python3 tools/translation-catalogs.py
python3 tools/translation-catalogs.py --check
```

The development helper compiles standard MO catalogs, generates the identity English catalog and verifies coverage, placeholders and plurals with Python's GNU gettext reader. It uses only Python's standard library; it does not translate strings or add a runtime dependency. CI also extracts the current source with WordPress CLI and checks the catalogs against that extraction.

For a future language, add its reviewed catalog and locale/endonym to `Language::LANGUAGES`, include its artifacts in the runtime allowlist, and extend the catalog build/check and integration coverage. The selector consumes the registry; it needs no new UI layout. Confirm native plural rules, regional fallback, keyboard labels, wrapping, mobile, and (when relevant) right-to-left layout before advertising that language. No extra language is claimed until its translation and acceptance are complete.
