# FileWarden 0.1.19-beta.1

Bêta préparée à la demande du propriétaire pour corriger les dix signalements Plugin Check du 28 novembre 2026. Après ses essais en préproduction, le propriétaire a autorisé la publication GitHub avec tag, ZIP installable et empreinte SHA-256. Elle conserve les fonctionnalités, les fichiers, leurs liens et leurs droits de l’Alpha. Schéma SQL 9 inchangé.

- Métadonnées : `Tested up to: 7.1`, branche déjà testée par la recette Alpha, et version du paquet cohérente dans les en-têtes PHP/readme. Le champ technique `Stable tag` correspond à cette Bêta pour les contrôles du paquet ; aucune soumission à l’annuaire ni désignation comme version stable n’est effectuée.
- Traductions : retrait de `load_plugin_textdomain`, en conservant le chargement explicite du catalogue embarqué au démarrage et les filtres limités au domaine FileWarden. Le choix FR/EN indépendant de WordPress et le repli anglais restent requis.
- SQL : prédicats fixes et paramètres préparés pour la lecture/purge du journal, les collections, les composants de sauvegarde et le contrôle des tables. Les capacités, confirmations, limites, transactions, filtres Action/Statut et la compatibilité des anciennes sauvegardes restent applicables.
- Compatibilité MySQL strict : une date de filtre vide est convertie en NULL dans les comparaisons du journal, pour éviter une erreur de date invalide même lorsque le filtre est désactivé. Les dates renseignées conservent leurs bornes inclusives ; lecture, revue et purge utilisent la même règle.

## Validation et limite connue

Recette locale : 122 tests unitaires / 436 assertions, huit tests JavaScript, PHPCS et syntaxe PHP, catalogues FR/EN, mises à jour Alpha → Bêta sur WordPress 6.8 et 7.1.5, contrôles HTTP/ACL/CSRF, cinq parcours Chromium/Firefox EN/FR sur ordinateur/mobile et restauration chiffrée entre installations. Les tests SQL ciblés couvrent 133 combinaisons Action/Statut, valeurs littérales, purge bornée et rollback, accès refusés, quatre périmètres de sauvegarde et empreintes des tables. La publication est conditionnée aux contrôles GitHub du commit et du tag.

PCP officiel 2.2.0 ne signale aucune erreur ni aucun avertissement lors des contrôles locaux en ligne de commande. Sur la préproduction du propriétaire, le contrôle Performance de l’interface PCP `enqueued_scripts_size` s’interrompt avec HTTP 400 / corps `0`. Le [signalement PCP #1445](https://github.com/WordPress/plugin-check/issues/1445) décrit une séquence correspondante liée à l’environnement de test. La cause exacte sur cet hébergement n’est pas établie ; ce contrôle distant reste **indéterminé, pas validé**. Les résultats CLI ne certifient pas le fonctionnement du coordinateur AJAX de PCP.

Installer **filewarden-0.1.19-beta.1.zip**, joint à cette préversion, en remplacement de FileWarden. Les archives automatiques Source code ne sont pas le paquet installable. Une empreinte SHA-256 est jointe pour vérifier le téléchargement. Le ZIP reste destiné aux tests en préproduction ; un contrôle PCP ne constitue pas à lui seul un audit de sécurité complet. Aucune soumission à WordPress.org n’est effectuée.
