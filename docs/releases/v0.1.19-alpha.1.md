# FileWarden 0.1.19-alpha.1

Première **Alpha publique**, après validation du dernier candidat v0.1.19-dev par le propriétaire en préproduction. Cette préversion regroupe les évolutions v18/v19 depuis la dernière release publique v0.1.17-dev. Elle est destinée aux essais et aux retours ; ce n’est pas une version stable ni une certification de sécurité de l’hébergement.

## Bibliothèque

- Renommage des documents et dossiers avec liens permanents conservés, sélection multiple et confirmations de déplacement, classement, restauration et mise à la corbeille.
- Recherche autorisée dans le dossier ou la bibliothèque, filtres et tri dans les en-têtes, date d’arrivée dans le dossier distincte de la date d’import.
- Fiche document centrée, description facultative de 400 caractères Unicode, recherche par nom ou description ; les descriptions restent des métadonnées privées.
- Doublons exacts : taille et SHA-256 serveur, puis comparaison des octets privés. Seuls les documents consultables sont signalés. Un même nom ne bloque plus l’avertissement : le nom libre de la copie est annoncé avant confirmation, revérifié sous verrou et ne remplace jamais l’original.
- Comprendre l’accès par étapes : fichier, dossier actuel, ancêtres et règles conservées. Toutes les contraintes s’appliquent ensemble. Enregistrer explicitement les droits remplace aussi les anciennes restrictions, en une transaction auditée ; un déplacement seul les conserve.
- Pictogrammes fournis pour les extensions, repli FILE pour les extensions inconnues, lecteur PDF compact et modales homogènes sur ordinateur/mobile.

## Publication et réglages

- Palettes FileWarden, Neutre, Nature, FileWarden sombre, Terracotta et Personnalisé ; nom public et logo PNG/JPEG, aperçu ordinateur/mobile et styles d’accès refusé.
- Contrastes de texte AA/AAA : indication des paires contrôlées, sans certification de l’accessibilité complète.
- Connexion WordPress, URL personnalisée HTTP(S) ou popup Elementor. L’identifiant ou le code court Elementor peut être saisi ; Elementor Pro doit être disponible sur la page, avec repli WordPress.
- Diagnostic de l’environnement, du chiffrement, du stockage, des tables et des sauvegardes. Conversion volontaire et bornée des tables nécessaires vers InnoDB, avec confirmations explicites ; aucune conversion automatique.
- Journal d’audit : filtres Action/Statut, exports et collecte IP facultative avec expiration, désactivée par défaut.

## Sauvegarde et compatibilité

Sauvegarde complète ou personnalisée, paquet chiffré/authentifié par Sodium et clé dérivée par Argon2id. Les comptes, mots de passe WordPress et clés du stockage source ne sont pas exportés. Les restaurations de bibliothèque exigent une destination vide ; la configuration seule peut être restaurée sur une bibliothèque existante. Sans reprise des droits, le contenu restauré reste privé et réservé à la gestion.

Schéma SQL 9 additif, manifeste 3 ; anciens manifestes 1/2 et schémas de sauvegarde 6/7/8 lisibles. Les anciennes dates d’arrivée inconnues restent vides. Une tâche existante peut se terminer avant une migration différée. Les documents et leur stockage restent séparés du code de l’extension lors d’une mise à jour.

Installer le fichier **filewarden-0.1.19-alpha.1.zip** joint à cette release dans WordPress, en remplacement de FileWarden. Les archives automatiques Source code ne sont pas le paquet installable. L’empreinte SHA-256 est jointe séparément.

## Validation et limites

Le candidat fonctionnel a passé 122 tests unitaires / 436 assertions, huit tests de transport JavaScript, les vérifications PHP/JS/PHPCS et les catalogues FR/EN. Les recettes locales couvrent Chromium/Firefox, ordinateur/mobile, refus d’accès et CSRF, doublons, transactions, migrations et restaurations chiffrées entre installations. Le propriétaire a confirmé le bon fonctionnement du dernier ZIP en préproduction avant ce passage en Alpha. La publication du tag est conditionnée aux contrôles GitHub Actions sur son commit ; leurs résultats restent la référence de la validation distante.

Cibles : WordPress 6.8+, PHP 8.2+, site unique. Les essais locaux ne prouvent pas toutes les combinaisons d’hébergement ni une validation humaine complète d’accessibilité. Le Diagnostic du site doit confirmer la disponibilité de Sodium et la protection du stockage. Limites actuelles des sauvegardes : tâches d’une heure, 10 000 lignes par table, manifeste de 4 Mio, 256 Mio par document et limite d’envoi PHP pour l’import.

Les liens de partage temporaires, l’historique des versions et l’historique individuel des documents restent différés. Les intégrations natives Gutenberg/Elementor restent à venir ; le code court fonctionne dans leurs blocs/widgets Code court.
