# FileWarden 0.1.15-dev

Cette préversion regroupe la correction de compatibilité MyISAM/InnoDB et les huit améliorations visuelles validées pour le back-office. Les dix évolutions originales et leurs protections sont conservées.

- Tables InnoDB imposées pour les nouvelles installations ; diagnostic et réparation explicite des anciennes tables MyISAM depuis **Réglages → Stockage et sécurité**.
- Illustration PNG fournie pour l’accueil Documents, à taille contenue.
- Logo officiel dans les en-têtes du plugin et dossier sécurisé en contour dans le menu WordPress.
- Pictogrammes ordinateur/bibliothèque pour l’ajout de documents.
- Repères colorés et catégories dans le journal simplifié ; vue technique et formats d’export conservés.
- Boutons de purge harmonisés avec les autres suppressions.
- Navigation compacte à onglets soulignés et pictogrammes.
- Bandeau d’état synthétique avec détails dépliables et alertes visibles.

## Installation et anciennes tables MyISAM

Télécharger **filewarden-0.1.15-dev.zip**, puis le téléverser via WordPress → Extensions → Ajouter → Téléverser une extension, en remplaçant FileWarden. Les archives automatiques « Source code » ne sont pas le paquet installable.

**Sauvegarder la base complète, la clé de chiffrement et le stockage avant la mise à jour et avant toute conversion.** Le stockage documentaire reste séparé du plugin ; le schéma 6 et les paramètres existants sont conservés.

Si la suppression signale des tables MyISAM : ouvrir **FileWarden → Réglages → Stockage et sécurité**, suspendre les écritures externes, confirmer la sauvegarde puis cliquer sur **Vérifier et réparer les tables de la base**. La conversion n’est pas lancée automatiquement lors d’une simple mise à jour. Vérifier le message de réussite, puis réessayer la suppression du dossier.

Un `ALTER TABLE` peut exiger temps, espace disque et permissions SQL. En cas d’interruption, la conversion peut être partielle : le plugin garde son contrôle d’intégrité et bloque les écritures tant que la reprise n’est pas vérifiée. Résoudre le problème avec l’hébergeur puis relancer l’action ; ne pas réinitialiser les tables ni effacer le point de reprise. Aucun document n’est effacé par cette réparation.

Le ZIP joint est celui installé et testé par la CI, accompagné de son SHA-256. Voir [le lot et sa matrice de conformité](../lot-v0.1.15-dev.md). La validation sur l’hébergement cible reste nécessaire ; cette version est une **préversion de développement**, sans certification de sécurité.
